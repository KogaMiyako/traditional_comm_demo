### 1.1 参数怎么理解

命令中的 `--参数` 是命令行选项，格式是：

```bash
命令 --参数名 参数值
```

例如：

```bash
--kind image
```

表示本次任务处理图片。参数值中的 `<run_id>` 是占位符，不能原样复制，需要替换成接收端实际生成的运行目录名。

### 1.2 所有命令通用参数

| 参数 | 作用 | 什么时候使用 | 示例 |
| --- | --- | --- | --- |
| `--config` | 指定 JSON 配置文件 | 使用非默认配置、修改模型或路径时 | `--config config/default.json` |
| `--kind` | 指定媒体类型 | `task-run`、`task-infer`、`tcp-send` 必填 | `text`、`image`、`video` |
| `--input` | 指定输入文件 | 直接处理图片、TVID 视频或 MOSEI `.pkl` 时使用 | `--input samples/sample.ppm` |
| `--runs` | 指定结果根目录 | 想把不同实验分开放置时使用 | `--runs runs/experiments/exp1` |
| `--task-id` | 给本次任务命名 | 方便在 `config.json`、`result.json` 中区分实验 | `--task-id image-reconstruction-01` |
| `--task-type` | 指定任务类型 | 决定是重建、分类还是情感分析 | `image_classification` |
| `--output-type` | 指定任务输出类型 | 主要用于 TCP 发送任务 | `reconstruction` 或 `structured` |

常用的 `--kind` 和 `--task-type` 对应关系：

| 任务 | `--kind` | `--task-type` | 输入 |
| --- | --- | --- | --- |
| 文本重建 | `text` | `text_reconstruction` | `.txt` |
| 图像重建 | `image` | `image_reconstruction` | `.ppm` |
| CIFAR-10 分类 | `image` | `image_classification` | CIFAR-10 或 `.ppm` |
| 视频重建 | `video` | `video_reconstruction` | `.tvid` |
| MOSEI 情感 | `video` | `video_sentiment` | `.pkl` 特征文件 |

路径按当前终端的工作目录解释。最稳妥的方式是先执行：

```bash
cd "$PYTHON_DIR"
```

### 1.3 `task-run` 参数

`task-run` 运行完整的本地回环链路：编码、分块传输、解码和任务推理。

| 参数 | 作用和取值 |
| --- | --- |
| `--dataset cifar10` | 从 CIFAR-10 batch 文件取样本。目前只有 CIFAR-10 数据集适配器。 |
| `--split train/test` | CIFAR-10 使用训练集或测试集；演示通常使用 `test`。 |
| `--sample-mode random` | 按随机种子随机选一张图片。 |
| `--sample-mode first` | 选择第 0 张图片。 |
| `--sample-mode index` | 与 `--sample-index N` 配合，选择固定下标。 |
| `--sample-index N` | 指定 CIFAR-10 样本下标，例如 `0`。复现实验时使用。 |
| `--seed N` | `random` 模式下控制随机选择结果，例如 `--seed 100`。 |
| `--chunk-size N` | 回环传输分块大小，单位字节；例如 `512` 用于测试小分块。 |
| `--delay-ms N` | 每个分块的模拟延时，单位毫秒；例如 `1`。 |
| `--loss-rate N` | 模拟丢块比例，取值范围 `[0,1)`；`0.01` 表示约 1% 丢块。 |
| `--jpeg-quality N` | JPEG 的 FFmpeg 质量参数，允许 `2` 到 `31`，默认 `3`；数值越小通常质量越高、载荷越大。 |
| `--h264-crf N` | H.264 恒定质量参数，允许 `0` 到 `51`；数值越小质量越高、文件越大。 |
| `--h264-preset NAME` | H.264 编码速度/压缩率预设，例如 `ultrafast`、`fast`、`medium`。 |

使用 `--dataset` 时通常不再写 `--input`；使用 `--input` 时表示直接给定文件路径。

### 1.4 `task-infer` 参数

`task-infer` 直接运行下游模型，不执行媒体编码和通信传输，适合 MOSEI `.pkl` 特征。

| 参数 | 作用和取值 |
| --- | --- |
| `--kind image/video` | 指定输入语义类型；MOSEI 特征虽然是 `.pkl`，仍使用 `--kind video`。 |
| `--input PATH` | 必填，指定图片或 MOSEI 特征文件。 |
| `--task-type image_classification` | 运行图像分类。 |
| `--task-type video_sentiment` | 运行 MOSEI 情感回归。 |
| `--split train/dev/test` | 对包含完整分片的 MOSEI 文件指定分片；单样本 `.pkl` 通常不需要。 |
| `--sample-index N` | 从完整 MOSEI 文件中选择第 N 个样本。 |
| `--ground-truth-label N` | 给图像分类提供真实类别，用于计算 `top1/top5`。 |
| `--ground-truth-score X` | 给 MOSEI 提供真实情感分数，用于计算单样本 MAE 等指标。 |

只有在需要评估分类是否命中时，才增加：

```bash
--ground-truth-label 3
```

只有在输入文件本身没有标签、但你知道真实情感分数时，才增加：

```bash
--ground-truth-score 0.33333334
```

### 1.5 `tcp-receive` 参数

`tcp-receive` 在一个终端启动接收端，必须保持运行，等待另一个终端执行 `tcp-send`。

| 参数 | 作用和取值 |
| --- | --- |
| `--bind` | 接收端监听地址。本机测试使用 `127.0.0.1`；允许局域网其他机器连接时使用 `0.0.0.0`。 |
| `--port` | TCP 监听端口。发送端的 `--port` 必须相同，例如 `5001`。 |
| `--output` | 接收端结果根目录，会保存收到的载荷、解码文件和 `receiver_result.json`。 |
| `--max-connections 1` | 收到 1 个业务 payload 后退出，适合单个实验。 |
| `--max-connections 2` | 收到 2 个业务 payload 后退出，适合连续测试图像重建和分类。 |
| `--max-connections 0` | 持续服务，不自动退出；需要按 `Ctrl+C` 停止。 |

发送端的健康检查连接不会计入 `max-connections`。

### 1.6 `tcp-send` 参数

`tcp-send` 在另一个终端连接接收端，执行编码、发送、等待 ACK、解码和任务推理。

| 参数 | 作用和取值 |
| --- | --- |
| `--host` | 接收端 IP 或主机名。本机使用 `127.0.0.1`。 |
| `--port` | 接收端端口，必须与 `tcp-receive` 相同。 |
| `--kind` | `text`、`image` 或 `video`，决定使用 UTF-8、JPEG 或 H.264/MP4。 |
| `--input` | 待发送的原始输入文件。图像通常是 `.ppm`，视频重建是 `.tvid`。 |
| `--task-type` | 发送后执行的任务，例如 `image_reconstruction`、`image_classification`、`video_reconstruction`。 |
| `--output-type` | 任务输出类型；重建使用 `reconstruction`，分类使用 `structured`。 |
| `--runs` | 发送端结果目录。接收端目录由接收端的 `--output` 决定。 |
| `--connect-timeout-ms` | 建立 TCP 连接超时，单位毫秒。 |
| `--receive-timeout-ms` | 等待接收端 ACK 超时，单位毫秒。 |
| `--jpeg-quality` | 临时覆盖配置中的图片编码质量。 |
| `--h264-crf` | 临时覆盖配置中的 H.264 CRF。 |
| `--h264-preset` | 临时覆盖配置中的 H.264 预设。 |

MOSEI 的 `.pkl` 不应写成 `tcp-send --kind video`，因为该命令的 `video` 指 TVID1/H.264 视频重建，不是 MOSEI 特征传输。

### 1.7 `demo_all.py` 参数

只有需要一次性演示多个任务时才使用 `demo_all.py`：

| 参数 | 作用 |
| --- | --- |
| `--config PATH` | 指定配置文件。 |
| `--output-dir PATH` | 覆盖默认的 `runs/demo_all`。 |
| `--host HOST` | 双端测试监听地址，默认 `127.0.0.1`。 |
| `--image-port N` | 图像双端端口，默认 `5001`。 |
| `--video-port N` | MOSEI 特征双端端口，默认 `5002`。必须与图像端口不同。 |
| `--skip-loopback` | 不运行本地回环，只运行双端部分。 |
| `--skip-dual` | 不启动 TCP 双端，只运行本地回环部分。 |

如果只运行一个实验，不需要使用 `demo_all.py`，直接使用后面的 `task-run`、`task-infer` 或 `tcp-send/tcp-receive` 命令。

## 6. 单独运行 TCP 双端实验

TCP 双端需要两个终端。下面以本机回环地址 `127.0.0.1` 和端口 `5001` 为例。

### 6.1 图像重建双端

终端 A：

```bash
cd "$PYTHON_DIR"
"$BASICTS_PYTHON" -m traditional_comm.cli tcp-receive \
  --config config/default.json \
  --bind 127.0.0.1 \
  --port 5001 \
  --output runs/experiments/tcp_image_reconstruction_receiver \
  --max-connections 1
```

终端 B：

```bash
cd "$PYTHON_DIR"
"$BASICTS_PYTHON" -m traditional_comm.cli tcp-send \
  --config config/default.json \
  --host 127.0.0.1 \
  --port 5001 \
  --kind image \
  --input samples/sample.ppm \
  --task-type image_reconstruction \
  --output-type reconstruction \
  --task-id tcp-image-reconstruction \
  --runs runs/experiments/tcp_image_reconstruction_sender
```

### 6.2 图像分类双端

先确保已经生成 `samples/selected/cifar10-test-00000.ppm`，然后终端 A 启动接收端：

```bash
"$BASICTS_PYTHON" -m traditional_comm.cli tcp-receive \
  --config config/default.json \
  --bind 127.0.0.1 \
  --port 5001 \
  --output runs/experiments/tcp_image_classification_receiver \
  --max-connections 1
```

终端 B 发送分类图片：

```bash
"$BASICTS_PYTHON" -m traditional_comm.cli tcp-send \
  --config config/default.json \
  --host 127.0.0.1 \
  --port 5001 \
  --kind image \
  --input samples/selected/cifar10-test-00000.ppm \
  --task-type image_classification \
  --output-type structured \
  --task-id tcp-cifar10-classification \
  --runs runs/experiments/tcp_image_classification_sender
```

`tcp-send` 会在发送端完成分类推理；接收端会保存 JPEG、解码后的 PPM 和 `receiver_result.json`。如需在接收端再次推理，使用接收结果中的 `decoded_path`：

```bash
"$BASICTS_PYTHON" -m traditional_comm.cli task-infer \
  --config config/default.json \
  --kind image \
  --input runs/experiments/tcp_image_classification_receiver/<run_id>/decoded.ppm \
  --task-type image_classification \
  --ground-truth-label 3 \
  --task-id tcp-cifar10-classification-receiver \
  --runs runs/experiments/tcp_image_classification_receiver/task
```

## 7. MOSEI 双端实验说明

MOSEI 输入是 `.pkl` 特征文件，不能直接使用 `tcp-send --kind video`，因为该命令的 `video` 载荷是 TVID1 → H.264/MP4。当前项目的 MOSEI 双端演示使用 `demo_all.py` 内置的 `mosei-feature-tcp-v1` 特征帧协议。

如果只需要单独验证 MOSEI 模型，不启动任何 TCP 端口，使用第 4.5 节的 `task-infer` 命令。

如果需要验证当前已实现的 MOSEI 特征双端，执行：

```bash
"$BASICTS_PYTHON" demo_all.py --skip-loopback
```

该命令会启动图像双端和 MOSEI 双端两个端口；如果要只启动 MOSEI 特征端，需要后续增加独立的 `mosei-feature-receive/mosei-feature-send` CLI，目前没有把该内部协议拆成两个独立命令。

## 8. 查看结果和指标

单个实验目录通常包含：

重点指标：

| 任务 | 指标 |
| --- | --- |
| 图像重建 | `psnr`，越高越好；`ssim`、`lpips` 当前为 `null`。 |
| CIFAR-10 分类 | `prediction.label`、`label_name`、`confidence`、`top_k`、`top1`、`top5`。 |
| MOSEI 情感 | `sentiment_score`、`label`、`mae`、`correlation`、`accuracy`、`f1`。 |
| 通信链路 | `input_bytes`、`encoded_payload_bytes`、`actual_link_total_bytes`、`end_to_end_latency_ms`、吞吐。 |

单个 MOSEI 样本无法计算 correlation，因此该字段为 `null` 是正常现象。

## 10. 一键演示和单实验命令的区别

```bash
# 单实验：只运行一个命令对应的任务
"$BASICTS_PYTHON" -m traditional_comm.cli task-run ...

# 全部演示：会依次启动回环、图像双端和 MOSEI 双端
"$BASICTS_PYTHON" demo_all.py
```

日常调试和演示单项效果时，优先使用本清单中的单实验命令；需要一次性展示完整链路时，再使用 `demo_all.py`。
