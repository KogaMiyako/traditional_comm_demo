# 传统通信任务运行说明

本文档说明主项目中图像/视频重建、CIFAR-10 图像分类和 MOSEI 视频情感分析的运行方式，以及本地回环和本地模拟双端发送的区别。

按实验逐项执行的完整命令清单见：[传统通信实验命令清单](传统通信实验命令清单.md)。

## 1. 运行准备

项目目录：

```text
KogaMiyako_traditional_comm_demo/
├── traditional_comm_py/              # Python 传统通信入口
├── imagec_and_MMSA/artifacts/checkpoints/
│   ├── resnet18-cifar10-v1.pt        # CIFAR-10 最佳模型
│   └── mmsa-mosei-v1.pt               # MOSEI 最佳模型
└── dataset -> ../data                 # 本地已上传数据的链接
```

进入 Python 通信目录，并使用包含 PyTorch、torchvision 和 FFmpeg 的环境：

```bash
cd /home/longxiang/traditional_comm_demo/KogaMiyako_traditional_comm_demo/traditional_comm_py
conda activate BasicTS
python -c "import torch; print(torch.__version__)"
ffmpeg -version
```

所有命令默认使用 `config/default.json`。数据、checkpoint、编码参数和任务映射都在该文件中配置。

先生成基础重建样本：

```bash
python -m traditional_comm.cli generate-samples
```

生成的文件位于 `traditional_comm_py/samples/`：

- `sample.ppm`：原始 RGB 图片，用于 JPEG 传统通信。
- `sample.tvid`：本地构造的原始 RGB 视频帧，用于 H.264/MP4 传统通信。
- `sample.txt`：UTF-8 文本，用于无损文本回环测试。

## 2. 三类任务

### 2.1 图片重建

图片重建只验证“原始图片 → JPEG → 接收 → 解码”的重建质量，不调用分类模型：

```bash
python -m traditional_comm.cli task-run \
  --config config/default.json \
  --kind image \
  --input samples/sample.ppm \
  --task-type image_reconstruction \
  --task-id image-reconstruction-demo
```

也可以直接使用 CIFAR-10 测试集样本。程序会读取 CIFAR-10 Python batch，生成 PPM 后进入相同的 JPEG 流程：

```bash
python -m traditional_comm.cli task-run \
  --config config/default.json \
  --kind image \
  --dataset cifar10 \
  --task-type image_reconstruction \
  --sample-mode index \
  --sample-index 0 \
  --task-id cifar10-image-reconstruction
```

视频重建使用本地 `TVID1` 样本，经过 H.264/MP4 编码和解码：

```bash
python -m traditional_comm.cli task-run \
  --config config/default.json \
  --kind video \
  --input samples/sample.tvid \
  --task-type video_reconstruction \
  --task-id video-reconstruction-demo
```

文本重建也可以运行，但不经过有损媒体编码：

```bash
python -m traditional_comm.cli task-run \
  --config config/default.json \
  --kind text \
  --input samples/sample.txt \
  --task-type text_reconstruction \
  --task-id text-reconstruction-demo
```

### 2.2 CIFAR-10 图片分类

图片分类会先经过完整的 JPEG 传统通信链路，再把接收端解码出的 PPM 图片送入 ResNet18：

```bash
python -m traditional_comm.cli task-run \
  --config config/default.json \
  --kind image \
  --dataset cifar10 \
  --task-type image_classification \
  --sample-mode index \
  --sample-index 0 \
  --task-id cifar10-classification-demo
```

`--sample-mode` 可选 `random`、`first`、`index`；严格复现实验时使用 `--sample-mode index --sample-index N`。CIFAR-10 标签会被写入任务上下文，因此本地任务结果可以计算该样本的 `top1` 和 `top5`。

当前接入的 checkpoint 是 `resnet18-cifar10-v1.pt`。训练集级指标保存在 `imagec_and_MMSA/artifacts/metrics/cifar10_test.json`；最佳 checkpoint 为第 62 轮，Top-1 为 0.8699，Top-5 为 0.9956。

### 2.3 MOSEI 视频情感分析

当前 MOSEI 输入是预计算的文本、音频和视觉特征文件，不是可以直接交给 H.264 编解码器的 MP4。因此使用特征级任务入口 `task-infer`：

```bash
python -m traditional_comm.cli task-infer \
  --config config/default.json \
  --kind video \
  --input ../imagec_and_MMSA/data/MOSEI/sample_test.pkl \
  --task-type video_sentiment \
  --split test \
  --sample-index 0 \
  --task-id mosei-sentiment-demo
```

该命令直接把 MOSEI 样本送入 MMSA LF-DNN checkpoint，不经过 MP4 编码。当前训练集级指标保存在 `imagec_and_MMSA/artifacts/metrics/mosei_test.json`：MAE=0.6409、correlation=0.6370、Has0 accuracy=0.7391、Has0 F1=0.7487。

单样本输出包含 `sentiment_score` 和 `label`。如果输入样本带真实分数，程序会计算该样本的 MAE、符号 accuracy 和 F1；单个样本无法定义 correlation，因此该字段为 `null`，这不是训练失败。

## 3. 本地回环模式

`task-run` 使用 `LoopbackTransport`。它在同一个 Python 进程内完成：

```text
原始输入
  -> 编码（JPEG 或 H.264/MP4）
  -> 内存分块传输（LoopbackTransport）
  -> 接收端重组
  -> 解码
  -> 重建任务或下游模型推理
```

这是单机功能验证模式，不创建 TCP socket，也不代表真实网络吞吐。可以用以下参数模拟分块、时延和丢失：

```bash
python -m traditional_comm.cli task-run \
  --config config/default.json \
  --kind image \
  --dataset cifar10 \
  --task-type image_classification \
  --sample-mode index --sample-index 0 \
  --chunk-size 512 \
  --delay-ms 1 \
  --loss-rate 0.01
```

配置文件中的默认回环参数是：`chunk_size=16384`、`delay_ms=0`、`loss_rate=0`。丢包可能造成媒体无法完整解码，任务结果会标记为失败，这是链路压力测试的预期行为。

如果只想运行三个基础媒体样本的重建回环：

```bash
python -m traditional_comm.cli run --config config/default.json
```

该命令运行 `sample.txt`、`sample.ppm` 和 `sample.tvid`，不运行 CIFAR 分类或 MOSEI 情感模型。

## 4. 本地模拟双端发送

`LanTcpReceiver` 和 `LanTcpTransport` 模拟发送端、接收端分离的传统通信。即使发送端和接收端在同一台机器，也通过 `127.0.0.1` TCP socket 传输；两台机器时只需要替换接收端 IP。

### 4.1 启动接收端

终端 A：

```bash
python -m traditional_comm.cli tcp-receive \
  --config config/default.json \
  --bind 127.0.0.1 \
  --port 5000 \
  --output runs_receiver \
  --max-connections 1
```

接收端会先接受发送端的健康检查，再等待一个业务 payload，收到后保存结果并退出。持续服务可使用 `--max-connections 0`。

### 4.2 发送图片重建或分类任务

终端 B：

```bash
python -m traditional_comm.cli tcp-send \
  --config config/default.json \
  --host 127.0.0.1 \
  --port 5000 \
  --kind image \
  --input samples/sample.ppm \
  --task-id tcp-image-reconstruction \
  --task-type image_reconstruction \
  --output-type reconstruction \
  --runs runs_sender
```

分类任务只需替换任务参数：

```bash
--task-type image_classification --output-type structured
```

如果要发送带有 CIFAR-10 真实标签的样本，先执行一次 CIFAR `task-run`，再把生成的 `samples/selected/cifar10-test-00000.ppm` 作为 `--input`。TCP 发送命令本身只接收文件，不负责从 CIFAR batch 选择标签，因此该路径下分类结果通常只有预测和置信度，`top1/top5` 可能为 `null`。

### 4.3 发送视频重建任务

```bash
python -m traditional_comm.cli tcp-send \
  --config config/default.json \
  --host 127.0.0.1 \
  --port 5000 \
  --kind video \
  --input samples/sample.tvid \
  --task-id tcp-video-reconstruction \
  --task-type video_reconstruction \
  --output-type reconstruction \
  --runs runs_sender
```

MOSEI 情感分析的 `.pkl` 特征不是 TVID/MP4，不能直接使用 `tcp-send --kind video`。当前项目对 MOSEI 使用上面的 `task-infer` 特征级入口；如果后续需要把 MOSEI 特征也纳入双端传输，应新增专用的特征 payload/transport 适配，而不是伪装成视频帧。

### 4.4 一键演示全部功能

演示脚本会自动生成基础样本，并依次完成：

1. 本地回环图像重建；
2. 本地回环 CIFAR-10 图像分类；
3. 本地回环视频重建冒烟测试；
4. 本地 MOSEI 情感分析；
5. 图像双端 TCP 重建和分类；
6. MOSEI 特征双端 TCP 传输和接收端推理。

在 `traditional_comm_py/` 目录执行：

```bash
python demo_all.py
```

也可以从项目根目录直接执行：

```bash
python traditional_comm_py/demo_all.py
```

注意：`python -m traditional_comm.cli` 只应在 `traditional_comm_py/` 目录执行。项目根目录的 `traditional_comm/` 是 JavaScript 版本目录，不包含 Python 的 `cli.py`。

脚本默认使用两个不同的本地端口：图像双端使用 `127.0.0.1:5001`，MOSEI 特征双端使用 `127.0.0.1:5002`。端口和样本路径在 `config/default.json` 的 `demo` 节点中配置，也可以临时覆盖：

```bash
python demo_all.py --image-port 5101 --video-port 5102
```

只运行其中一部分时：

```bash
python demo_all.py --skip-loopback  # 只跑两个双端测试
python demo_all.py --skip-dual      # 只跑本地回环和任务推理
```

MOSEI 双端使用 `mosei-feature-tcp-v1` 特征帧协议传输 `.pkl`，接收端保存收到的特征后调用 `video_sentiment_infer.py`。因此它是真实的本地 TCP 双端验证，同时避免把预计算特征错误地当作 MP4 视频编码。

## 5. 运行结果在哪里

### 5.1 普通媒体任务

每次 `task-run` 或 `run` 都会在 `traditional_comm_py/runs/<run_id>/` 下生成：

```text
config.json             # 本次运行的输入、任务、编码和链路配置
metrics.json            # 通信、质量、资源和任务指标
transport.json          # Loopback 或 LAN TCP 的传输统计
result.json             # 最终任务结果、校验和、输出路径
encoded_payload.jpg     # 图片 JPEG 载荷
encoded_payload.mp4     # 视频 MP4 载荷
received_payload.*      # 接收端收到的编码载荷
output.*                # 可打开/播放的编码输出
decoded.ppm             # 图片解码结果
decoded.tvid            # 视频解码结果
```

### 5.2 MOSEI 特征级任务

`task-infer` 会在同一个 `runs/<run_id>/` 目录生成：

```text
config.json             # 标记 execution=task-only，并记录输入特征文件
metrics.json            # 推理时延和 task_result
result.json             # task_result、prediction、metrics、checkpoint
```

项目已经验证过的结果示例位于：

```text
traditional_comm_py/runs/final_validation/
```

其中图像运行的 `result.json` 包含 `cat`、Top-1/Top-5=1.0；MOSEI 运行的 `result.json` 包含 `positive` 和 `sentiment_score`。

## 6. 指标含义

### 6.1 通信和时延指标

| 字段 | 含义 |
| --- | --- |
| `input_bytes` | 原始输入大小。图片任务是 PPM，视频重建任务是 TVID1。 |
| `encoded_payload_bytes` | 编码后的 JPEG 或 MP4 载荷大小。 |
| `actual_sent_bytes` / `actual_received_bytes` | 发送端发送和接收端收到的业务 payload 大小。 |
| `actual_link_total_bytes` | 实际链路总字节数。回环模式按 payload 统计；TCP 模式包含发送帧和接收 ACK 的线缆字节。 |
| `data_reduction_ratio` | `(input_bytes - encoded_payload_bytes) / input_bytes`，越高表示压缩后更小。 |
| `encode_time_ms` | 原始媒体编码为 JPEG/MP4 的耗时。 |
| `transport_time_ms` | Loopback 分块或 TCP 发送、接收 ACK 的耗时。 |
| `decode_time_ms` | 接收载荷解码为 PPM/TVID1 的耗时。 |
| `end_to_end_latency_ms` | 编码 + 传输 + 解码的端到端媒体链路耗时；task-only 时主要是任务推理耗时。 |
| `average_throughput_mbps` | 平均有效吞吐，单位 Mbps。 |
| `peak_throughput_mbps` | 当前实现记录的峰值吞吐；单次 payload 时通常与平均吞吐相同。 |
| `receiver_decode_valid` | 接收端是否能够成功解码。 |

### 6.2 重建质量指标

| 字段 | 含义 |
| --- | --- |
| `psnr` | 峰值信噪比，单位 dB，越高越好；当前图片/视频实现已计算。完全一致时返回 99.0。 |
| `ssim` | 结构相似度；当前基线未实现，返回 `null`。 |
| `lpips` | 感知相似度；当前基线未实现，返回 `null`。 |
| `content_match` | 文本字节是否完全一致；图片和视频使用有损编码，因此为 `null`。 |
| `output_valid` | 解码结果是否通过格式、尺寸和帧数校验，1 表示通过。 |

### 6.3 图像分类指标

| 字段 | 含义 |
| --- | --- |
| `prediction.label` | CIFAR-10 数字类别 ID。 |
| `prediction.label_name` | 类别名称，如 `cat`。 |
| `prediction.confidence` | Top-1 softmax 概率。 |
| `prediction.top_k` | 前 k 个类别及其概率，当前最多返回 5 个。 |
| `metrics.top1` | 有真实标签时，Top-1 是否命中；命中为 1.0，否则 0.0。无标签时为 `null`。 |
| `metrics.top5` | 有真实标签时，真实类别是否在前 5 名；命中为 1.0，否则 0.0。无标签时为 `null`。 |
| 训练集 `accuracy` / `f1` | checkpoint 对完整 CIFAR-10 测试集的总体指标，不是单张图片的指标。 |

### 6.4 MOSEI 情感指标

| 字段 | 含义 |
| --- | --- |
| `sentiment_score` | 回归情感分数，当前阈值为 0，分数大于等于 0 判为 positive。 |
| `label` | 根据阈值得到的 `positive` 或 `negative`。 |
| `mae` | 平均绝对误差，越低越好；单样本时是该样本绝对误差。 |
| `correlation` | 预测分数和真实分数的相关系数，越高越好；单样本或预测方差为 0 时为 `null`。 |
| `accuracy` | 正负号分类是否正确；训练结果中的 `Has0_acc_2` 包含 0 类。 |
| `f1` | 正负号分类 F1；训练结果中的 `Has0_F1_score` 是加 0 类口径。 |
| `Non0_acc_2` / `Non0_F1_score` | 排除真实标签为 0 的样本后的二分类 accuracy/F1。 |
| `Mult_acc_5` / `Mult_acc_7` | 将回归分数按 5 档或 7 档离散后的多级准确率。 |

## 7. 常见区别和排查

- `task-run`：真正执行编码、传输、解码和任务，默认是本地回环。
- `tcp-receive` + `tcp-send`：两个进程通过本地或局域网 TCP 模拟发送端和接收端，适合验证双端协议、ACK、校验和接收端结果文件。
- `task-infer`：面向 MOSEI 这类已经是模型输入特征的任务，不执行媒体编解码或 TCP 传输。
- 如果分类命令返回 `top1/top5=null`，通常是没有传入真实标签，不代表模型失败；使用 CIFAR `task-run --dataset cifar10` 可以带入标签。
- 如果 `ssim` 或 `lpips` 为 `null`，是当前基线没有实现这两个指标，不是解码失败。
- 如果出现 `ffmpeg not found`，需要在当前 Python 环境安装 FFmpeg，并确认 `ffmpeg -version` 可执行。
- 如果 TCP 测试出现端口占用，换用其他端口，并让发送端 `--port` 与接收端一致。

一键演示的输出目录默认为 `traditional_comm_py/runs/demo_all/`：

```text
runs/demo_all/
├── demo_summary.json                  # 全部任务的汇总 JSON
├── loopback/                          # 本地回环结果
└── dual_tcp/
    ├── image_sender/                  # 图像发送端结果
    ├── image_receiver/                # 图像接收端 payload、解码和 receiver_result.json
    ├── image_receiver_task/           # 接收端解码后的分类结果
    ├── video_sender/                  # MOSEI 特征发送统计
    └── video_receiver/                # 收到的 .pkl、result.json 和推理结果
```

查看结果时优先打开 `demo_summary.json`；查看单个任务的完整通信指标时打开对应运行目录下的 `metrics.json` 和 `result.json`。双端图像接收目录中的 `receiver_result.json` 还会记录接收字节数、SHA-256、解码是否成功和解码耗时。
