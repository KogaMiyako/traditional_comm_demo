# 内容2：下游任务适配实现说明

## 1. 本次改动目标

本次改动针对语义通信侧确定的三个任务重新整理传统通信的解码后处理：

```text
图像分类       <-> UDeepSC imgc
图像重建       <-> UDeepSC imgr
视频情感分析   <-> UDeepSC msa
```

UDeepSC 目录只作为参考代码，不作为本项目的运行时依赖，也不会提交到 Git。传统通信代码只依赖统一的任务适配接口，后续可以通过配置接入语义同学的推理程序。

本次没有修改 Web 页面，代码位于非 Web 分支：

```text
feature/task-adapter
```

当前本地数据目录为：

## 3. 配置文件的作用

配置文件控制以下内容：

- 数据集路径；
- 样本、运行结果和接收结果目录；
- 模型目录和 checkpoint 位置；
- CIFAR-10 和 MOSEI 数据集信息；
- 任务名称和 UDeepSC 任务名称的映射；
- 任务输入输出类型；
- 任务后端和推理命令；
- 模型版本和指标列表；
- JPEG/H.264 参数；
- Loopback 和 LAN TCP 参数；
- SNR sweep 配置。

配置中的相对路径是相对于配置文件所在目录解析的。例如：

```json
{
  "paths": {
    "dataset_root": "../../dataset"
  }
}
```

会解析为项目根目录下的 `dataset/`。

配置加载接口位于：

```python
from traditional_comm.config import load_config

config = load_config("config/default.json")
```

主要函数：

```text
load_config(path)
get_task_config(config, task_type)
get_dataset_config(config, dataset_name)
```

## 4. 通信和任务处理流程

传统通信一次运行的流程变为：

```text
读取原始图片/视频
       ↓
JPEG/H.264 编码
       ↓
TransportAdapter 发送和接收
       ↓
JPEG/H.264 解码
       ↓
TaskAdapter 下游任务处理
       ↓
保存 task_result、通信指标和任务指标
```

传统通信仍然只负责媒体编码、传输和解码。分类和情感分析不写进 `codecs.py` 或 `transport.py`，而是由任务适配器负责。

## 5. 新增任务接口

新增文件：

```text
traditional_comm_py/traditional_comm/config.py
traditional_comm_py/traditional_comm/task_adapter.py
traditional_comm_py/traditional_comm/task_metrics.py
```

任务接口：

```python
run(
    kind,
    source_path,
    decoded_path,
    source_bytes,
    decoded_bytes,
    task,
    quality,
) -> dict
```

其中：

| 参数 | 含义 |
|---|---|
| `kind` | `text`、`image` 或 `video` |
| `source_path` | 发送端原始输入文件 |
| `decoded_path` | 解码后的原始内容文件 |
| `source_bytes` | 原始输入字节 |
| `decoded_bytes` | 解码后内容字节 |
| `task` | 本次运行的任务配置 |
| `quality` | 已计算出的媒体质量指标 |

统一返回格式：

```json
{
  "task_id": "image_classification",
  "task_type": "image_classification",
  "semantic_task": "imgc",
  "dataset": "cifar10",
  "input_type": "decoded_image",
  "output_type": "structured",
  "success": true,
  "status": "completed",
  "prediction": {},
  "metrics": {},
  "inference_time_ms": 0,
  "model_version": "",
  "checkpoint": null,
  "error": null
}
```

## 6. 三个任务的当前适配方式

### 6.1 图像分类

配置中的任务名：

```text
image_classification
```

对应 UDeepSC：

```text
imgc
```

输入是传统 JPEG 解码后的图片，输出应包含：

```text
预测类别
置信度
Top-K 结果
```

指标预留：

```text
accuracy
F1
top1
top5
推理耗时
```

当前默认配置将该任务设置为 `command` 后端，但没有填写具体命令和 checkpoint，因此运行时会返回 `not_configured`，不会伪造分类结果。

### 6.2 图像重建

配置中的任务名：

```text
image_reconstruction
```

对应 UDeepSC：

```text
imgr
```

当前使用内置任务适配，不需要额外的机器学习模型。JPEG 解码后的图片就是传统通信的重建结果。

指标为：

```text
PSNR
SSIM
LPIPS
重建输出路径
```

现有本地样本使用 PPM 和 TVID1，因此质量计算继续使用当前的原始像素格式；正式 JPG/MP4 接入时，解码适配器仍然可以提供相同的任务结果字段。

### 6.3 视频情感分析

配置中的任务名：

```text
video_sentiment
```

对应 UDeepSC：

```text
msa
```

当前 MOSEI 数据是：

```text
视觉特征 + 文本特征 + 声学特征
```

因此当前配置明确标记为：

```text
input_type: mosei_features
label_type: regression
```

指标预留：

```text
情感分数
情感标签
MAE
相关系数
准确率
F1
推理耗时
```

需要注意，`dataset/MOSEI/*.pkl` 是已经提取好的特征文件，不是 MP4 视频。当前适配可以支持 MOSEI 特征任务，但不能把 `.pkl` 直接称为 H.264 视频传输结果。

如果后续要求真正传输 MP4，需要另行增加：

```text
MP4 解码
  -> 视频视觉特征提取
  -> 音频特征提取
  -> 字幕/语音文本提取
  -> 组合成 MOSEI 模型输入
```

这一部分必须由语义任务同学提供特征提取方式，否则无法保证传统和语义两端的输入一致。

## 7. UDeepSC 推理程序如何接入

传统通信不直接导入 `UdeepscFSM/model.py`。分类和视频情感任务使用配置的外部命令调用，以此隔离 Python 环境、CUDA、模型依赖和传统通信代码。

配置示例：

```json
{
  "backend": "command",
  "command": [
    "D:/miniconda3/envs/semantic/python.exe",
    "D:/local/UdeepscFSM/infer.py"
  ],
  "model": {
    "name": "UDeepSC_model",
    "version": "msa-v1",
    "checkpoint": "D:/local/checkpoints/msa.pth"
  }
}
```

任务命令从标准输入读取 JSON：

```json
{
  "task_type": "video_sentiment",
  "semantic_task": "msa",
  "dataset": "mosei",
  "input_path": "D:/.../decoded.tvid",
  "reference_path": "D:/.../sample.tvid",
  "task_config": {}
}
```

任务命令向标准输出返回 JSON：

```json
{
  "success": true,
  "prediction": {
    "sentiment_score": 0.72,
    "label": "positive"
  },
  "metrics": {
    "mae": 0.18,
    "f1": 0.81
  },
  "model_version": "msa-v1",
  "checkpoint": "D:/.../msa.pth"
}
```

这样将来替换 UDeepSC、替换 checkpoint 或切换 ARM64/x86_64 环境时，不需要修改传统通信的编码和传输代码。

## 8. 运行方式

生成并运行传统通信基础 Demo：

```powershell
Set-Location D:\workspace\SemCom\traditional_comm_py
& D:\miniconda3\envs\semcom-py\python.exe -m traditional_comm.cli demo `
    --config .\config\default.json
```

单独运行图像重建：

```powershell
& D:\miniconda3\envs\semcom-py\python.exe -m traditional_comm.cli task-run `
    --config .\config\default.json `
    --kind image `
    --input .\samples\sample.ppm `
    --task-type image_reconstruction
```

图像分类配置已经接入 `traditional_comm_py/image_infer.py`，可直接运行：

```powershell
& D:\miniconda3\envs\semcom-py\python.exe -m traditional_comm.cli task-run `
    --config .\config\default.json `
    --kind image `
    --input .\samples\sample.ppm `
    --task-type image_classification
```

使用 CIFAR-10 随机抽取一张测试图片时，不需要手动转换图片：

```powershell
& D:\miniconda3\envs\semcom-py\python.exe -m traditional_comm.cli task-run `
    --config .\config\default.json `
    --kind image `
    --dataset cifar10 `
    --task-type image_classification
```

默认从 `dataset/cifar` 的 `test` 集随机选择一张图片。随机选择使用配置中的 `seed`，因此同一个 seed 会重复选择同一张图片。若要固定样本，可以指定：

```powershell
--dataset cifar10 --split test --sample-mode index --sample-index 1234
```

选择出的 CIFAR-10 batch 数据会转换为临时 PPM 文件，再进入现有 JPEG 编码和传统通信流程；运行配置会记录数据集、split、样本 index、类别编号和类别名称。`samples/sample.ppm` 仍保留用于通信链路冒烟测试。

MOSEI 当前使用 MMSA 的文本、音频和视觉特征，不是 MP4 文件。因此使用 `task-infer` 直接对特征样本推理，不将 `.pkl` 文件误送入 H.264 编解码流程：

```powershell
& D:\miniconda3\envs\semcom-py\python.exe -m traditional_comm.cli task-infer `
    --config .\config\default.json `
    --kind video `
    --input ..\imagec_and_MMSA\data\MOSEI\sample_test.pkl `
    --task-type video_sentiment `
    --split test `
    --sample-index 0
```

两个外部推理程序均通过标准输入接收 JSON、通过标准输出返回 JSON；模型运行目录和 checkpoint 由 `config/default.json` 控制。详细字段和结果示例见 [内容2图像分类与 MOSEI 视频情感任务对接说明](内容2图像分类与MOSEI视频情感任务对接说明.md)。

局域网 TCP 发送时，可以使用：

```powershell
& D:\miniconda3\envs\semcom-py\python.exe -m traditional_comm.cli tcp-send `
    --config .\config\default.json `
    --host 192.168.1.20 `
    --kind image `
    --input .\samples\sample.ppm `
    --task-type image_classification
```

## 9. 结果文件

每次运行的目录仍然是：

```text
runs/<run_id>/
  config.json
  metrics.json
  transport.json
  result.json
  encoded_payload.*
  received_payload.*
  output.*
  decoded.*
```

其中 `metrics.json` 新增：

```json
{
  "task": {
    "content_match": null,
    "output_valid": 1,
    "task_result": {}
  }
}
```

`task_result` 中保存任务类型、UDeepSC 对应任务、预测结果、任务指标、推理耗时、模型版本、checkpoint 和错误信息。

通信失败、解码失败或任务未配置时，运行会记录为失败，并通过 `task_result.error` 返回原因，不会将空结果当作有效任务结果。
